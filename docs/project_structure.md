# Project Structure

Event Horizon is a Unity 6 project organized around assembly-defined C# modules. This page is a high-level, living map of the repository; add links to deeper documentation as individual areas are documented.

For the game itself, see [Game design](game.md). For how the parts work together, see [Architecture](architecture.md).

## Repository Root

- `Assets/` contains gameplay code, scenes, resources, art, editor tools, and vendored Unity plugins.
- `Packages/` declares Unity Package Manager dependencies. `manifest.json` is the primary package configuration. See [Build pipeline: Package dependencies](build.md#package-dependencies).
- `ProjectSettings/` stores project-wide Unity settings, including the editor version and per-platform build settings. See [Build pipeline: Platform settings](build.md#platform-settings).
- `docs/` contains contributor-facing documentation. `docs/game_design/` holds the [game design chapters](game_design/index.md); `docs/issues/` holds known defects by component.
- `UIElementsSchema/` contains schemas used by Unity UI authoring tools.
- `README.md` provides the public project and community overview.
- `.gitmodules` lists the 7 Git submodules. Each module doc describes its own submodule.
- `.issues/` holds local notes on GitHub issues. See [GitHub issue handling](../.issues/README.md).
- `TASKS.md` lists open and planned work. `TODO/` holds working plans and the documentation tools.
- `Experimental/` holds throwaway spikes for working plans, as standalone .NET projects outside `Assets/`. Game code never references them.

Git ignores these local folders. They are not part of a clone:

- `.server/` holds the PHP game server. See [Server](server.md).
- `Mods/` holds test mod databases. `Backups/` holds old copies of files. `MemoryCaptures/` holds Unity memory profiler captures.
- `graphify-out/` holds generated knowledge-graph output. Copies inside `Assets/` are imported by Unity.
- `Builds/` holds player builds. See [Build pipeline: Build outputs](build.md#build-outputs).
- The root `.csproj` files are generated by the IDE. Some of them have no matching assembly ([BL9](issues/build.md#bl9-stale-csproj-files-in-the-project-root)).

## Assets at a Glance

### Code and architecture

- `Assets/Scripts/` is the application layer: game-state flow, installers, domain coordination, services, GUI integration, and legacy code. See [Application layer](application_layer.md) and its [issues](issues/application_layer.md).
- `Assets/Editor/` contains the editor windows and build hooks. `Assets/Tools/` contains a vendored collider optimizer. See [Build pipeline: Editor tools](build.md#editor-tools) and [Build hooks](build.md#build-hooks).
- `Assets/ExpressionParser/` is a submodule with the formula compiler that database expressions use. See [Expression parser](expression_parser.md).

Assembly boundaries are defined by `.asmdef` files. Check references before moving code between modules.

## Modules

`Assets/Modules/` contains core game features and public service implementations.

- `AppConfiguration` - Generated application configuration plus shared font and UI theme assets. See [AppConfiguration module](app_configuration.md).
- `BattleSimulator` - Combat simulation, ship behavior, weapons, physics, and combat AI. See [BattleSimulator module](battle_simulator.md).
- `CommonComponents` - Shared value types (IDs, money, prices), galaxy layout, signals, and general helpers. See [CommonComponents module](common_components.md) and its [issues](issues/common_components.md).
- `Database` - Schema-driven game data, runtime access and serialization, migrations, and code-generation tools. See [Database module](database.md).
- `GalaxyMap` - Prefabs and materials that draw the star map. The scripts are in `Assets/Scripts/Legacy/Map/`. See [GalaxyMap module](galaxy_map.md).
- `GameServices` - Application lifecycle, the additive scene loader, and combat input with key rebinding. See [GameServices module](game_services.md).
- `GameSession` - Schema-driven session state, save/load support, and serialization code generation. See [GameSession module](game_session.md).
- `Quests` - Quest construction and runtime processing, including requirements, actions, fleets, and rewards. See [Quests module](quests.md).
- `ResourceLocator` - Runtime lookup of sprites and sound clips by name, with mod fallback. See [ResourceLocator module](resource_locator.md).
- `SecurityStub` - Open-source replacement for the private `Security` assembly. See [Services](services.md#securitystub).
- `Services` - Default or local implementations for settings, messaging, object pooling, audio, local saves, and stubs for online features. See [Services](services.md).
- `ServicesFacade` - Interfaces and shared contracts consumed by service clients and implementations. See [Services](services.md).
- `ShipConstructor` - Ship model, component compatibility, modifications, satellites, statistics, and game formulas. See [ShipConstructor module](ship_constructor.md).

## ModulesShared

`Assets/ModulesShared/` is a Git submodule that Event Horizon shares with Event Horizon: Frontier. A change here can break Frontier, and this repository cannot check that. See [Gui: Shared code constraint](gui.md#shared-code-constraint).

- `CombatSimulation` - New battle simulator, shared with Frontier. In progress: it holds only the engine-free physics library now. See [Combat simulation](combat_simulation.md).
- `Diagnostics` - Project logging, assertion, and Unity logger adapters. See [Diagnostics module](diagnostics.md).
- `Gui` - Shared UI framework, window management, themes, the debug console, and reusable controls. See [Gui module](gui.md).
- `Localization` - Runtime localization and language-specific XML translation resources. See [Localization module](localization.md).
- `Resources` - Shared GUI icons. See [Gui: Shared icons](gui.md#shared-icons) and [Sprites](resources/sprites.md).
- `ShipEditor` - Ship-layout editing context, scene integration, selection, and mesh-building tools. See [ShipEditor module](ship_editor.md).
- `Utilites` - Inventory collections, random-number generation, serialization helpers, and obscured value types. The directory name intentionally retains its existing spelling. See [Utilites module](utilites.md).

## ModulesPrivate

`Assets/ModulesPrivate/` is a private Git submodule with non-public or platform-specific implementations. The game also builds without it. See [ModulesPrivate](modules_private.md).

- `Plugins` - Private third-party integrations, including iOS Keychain and StansAssets wrappers. See [Plugins: iOS native plugins](plugins.md#ios-native-plugins).
- `Security` - Save and mod decryption, request creation, and bundle validation. See [ModulesPrivate: Security assembly](modules_private.md#security-assembly).
- `Services` - Platform implementations for accounts, ads, assets, in-app purchases, saves, and related services. See [ModulesPrivate](modules_private.md).

## Scenes, Data, and Media

- `Assets/Scenes/` contains entry and feature scenes such as `LoaderScene`, `MainMenuScene`, `StarMapScene`, and `CombatScene`. Each [game state](application_layer.md#states) lists the scenes it loads. See also [Build pipeline: Scenes in the build](build.md#scenes-in-the-build).
- `Assets/Resources/` and module-specific `Resources/` folders contain assets loaded at runtime. See [Media and resources](resources/index.md).
- `Assets/ScriptableObjects/` contains serialized configuration assets. See [Configuration and plugin Resources](resources/configuration.md).
- `Assets/Animation/`, `Audio/`, `Fonts/`, `Sprites/`, and `SplashImage/` contain presentation assets. See [Presentation](resources/presentation.md) and [Sound and music](resources/audio.md). `Assets/Default.mixer` is the audio mixer of `LoaderScene`.
- `Assets/BundledAssets/` holds the music that the build packs into an asset bundle. See [Server: Asset bundles](server.md#asset-bundles). `Assets/StreamingAssets/` is for raw platform files and is ignored by Git.
- `Assets/Plugins/` plus vendor-named folders contain third-party and platform-specific integrations. See [Plugins and third-party code](plugins.md).

## Tests and Generated Files

Tests are generally co-located with their assemblies under `Tests/`, for example `Assets/Modules/Database/Tests/` and `Assets/ModulesShared/Utilites/Tests/`. Expression parser tests live in `Assets/ExpressionParser/Tests/`.

Database and session modules include schemas and code generators in `.Schema/` and `.CodeGenerator/`. Use their checked-in scripts rather than hand-editing generated output. See [Database code generator](database/code_generator.md) and [GameSession code generator](game_session/code_generator.md).

Do not edit or commit Unity caches and local outputs such as `Library/`, `Temp/`, `obj/`, `Logs/`, `UserSettings/`, `Builds/`, generated IDE project files, or ignored platform plugin artifacts. Keep Unity `.meta` files with their corresponding assets.

## Where New Work Goes

- Add self-contained gameplay features to the closest assembly under `Assets/Modules/`.
- Put game-wide orchestration and scene integration in `Assets/Scripts/`. See [Application layer: Where new work goes](application_layer.md#where-new-work-goes).
- Put reusable infrastructure in `Assets/ModulesShared/` and platform/private implementations in `Assets/ModulesPrivate/`.
- Add tests beside the owning assembly in a `Tests/` folder with a test assembly definition.
