# GameServices Module

The GameServices module holds three runtime services that sit between Unity and the game: the application lifecycle (pause, focus, background), the additive scene loader used by the game state machine, and the combat input actions with key rebinding. It also contains a small legacy `Timer` class.

The module name is easy to confuse with the `Assets/Scripts/GameServices/` folder of the application layer (save manager, arena client, random generator). That folder is described in [Application layer: Game services](application_layer.md#game-services-gameservices).

## Application lifecycle

`IApplication` ([IApplication.cs](../Assets/Modules/ServicesFacade/Scripts/Application/IApplication.cs)) has `IsActive`, `Paused`, `Pause(sender)`, and `Resume(sender)`. `ServicesInstaller` creates one implementation on a new GameObject, chosen by platform (`UNITY_WEBGL`, `UNITY_STANDALONE`, `UNITY_IPHONE || UNITY_ANDROID`).

### Two kinds of pause

1. **System pause.** Unity calls `OnApplicationFocus` and `OnApplicationPause`. They set `_applicationFocused` and `_applicationPaused`. `IsActive` is true when the application is not paused and has focus. The standalone version also counts as active without focus when `IGameSettings.RunInBackground` is on.
2. **Game pause.** Code calls `Pause(sender)` and `Resume(sender)`. [`GamePauseCounter`](../Assets/Modules/ServicesFacade/Scripts/Application/IApplication.cs) keeps a set of senders. The game is paused while the set is not empty. Callers: [`ModalDialogState`](../Assets/Scripts/GameStateMachine/States/ModalDialogState.cs) and [`PauseGameHelper`](../Assets/Scripts/Gui/Combat/PauseGameHelper.cs) (combat menu).

`Paused` is `true` when either kind applies.

### Effects

On every change the service:

1. Sets `Time.timeScale` to 0 when paused, else 1.
2. Sets the static `Timer.Paused`.
3. Fires `GamePausedSignal(paused)`. `GameSettings` saves `PlayerPrefs` on it. (`GameDataManager` saves the game from its own `OnApplicationPause` and `OnApplicationFocus` callbacks, not from this signal.)
4. On mobile and WebGL, sets `Screen.sleepTimeout`: the screen never sleeps while the game runs.

Focus and pause changes also fire `AppActivatedSignal(isActive)`. `MusicPlayer` mutes and `SoundPlayer` pauses on it.

The mobile and standalone versions fire both signals on every focus or pause callback, even when `IsActive` does not change. The WebGL version fires only when `IsActive` changes. The WebGL "in background" detection used a third-party package (`Agava.WebUtility`); those lines are commented out.

## Scene manager

[`GameSceneManager`](../Assets/Modules/GameServices/Scripts/SceneManager/GameSceneManager.cs) is a `MonoBehaviour` on a new GameObject in the root container. The [state machine](application_layer.md#game-state-machine) is its only client. It passes the union of the scenes that all states on the stack need.

`Load(scenes)`:

1. Sets `State = Loading` and fires `SceneManagerStateChangedSignal`.
2. Stores the requested set in `_requiredScenes`.
3. For each required scene that is neither active nor loading, calls `SceneManager.LoadSceneAsync(name, Additive)`.
4. For each active scene that is not required: fires `SceneBeforeUnloadSignal(scene)`, deactivates its root objects, and calls `UnloadSceneAsync`. Per-scene `Messenger` instances clean up on this signal.
5. If nothing is loading, sets `State = Ready` at once.

`OnSceneLoaded` moves the scene from loading to active and fires `SceneLoadedSignal`. When the last scene is loaded, the state becomes `Ready` and the state machine activates the top state.

An unknown scene name (not in `GameScene`) calls `Debug.Break()`. A scene that is no longer required when it finishes loading is unloaded again; see [GS1](issues/game_services.md#gs1-a-scene-dropped-while-loading-leaves-the-manager-in-loading).

`Initialize` records the scenes that are already open (normally `LoaderScene`). Scene names come from [`GameScene.ToSceneName`](services.md#scene-names).

## Input

The combat input uses the Unity Input System. [`InputActions.inputactions`](../Assets/InputActions.inputactions) has two action maps and no control schemes.

| Map | Action | Type | Default bindings |
| --- | --- | --- | --- |
| Combat | `Horizontal` | Axis | A/D, Left/Right arrows, gamepad D-pad X |
| Combat | `Vertical` | Axis | S/W, Down/Up arrows, gamepad D-pad Y |
| Combat | `Move` | Vector2 | Gamepad left stick |
| Combat | `Fire1` | Button | 1, Space, gamepad South |
| Combat | `Fire2`–`Fire4` | Button | 2–4, gamepad East, West, North |
| Combat | `Fire5`, `Fire6` | Button | 5, 6, gamepad left and right trigger |
| Mouse | `MouseLook` | PassThrough Vector2 | Mouse position |
| Mouse | `Thrust` | Button | Left mouse button |
| Mouse | `Action1` | Button | Right mouse button |
| Mouse | `Action2` | Button | Middle mouse button |

Consumers in the [BattleSimulator module](battle_simulator.md): `InputSystemKeyboard` ([Keyboard.cs](../Assets/Modules/BattleSimulator/Scripts/Combat/AI/Keyboard.cs)) and `InputSystemMouse` ([Mouse.cs](../Assets/Modules/BattleSimulator/Scripts/Combat/AI/Mouse.cs)). Each creates its own `InputActions` instance.

### Key rebinding

[`Configuration`](../Assets/Modules/GameServices/Scripts/Input/Configuration.cs) stores overrides for nine bindings: `Left`, `Right` (the first `negative` and `positive` parts of `Horizontal`), `Up` (the first `positive` part of `Vertical`), and binding 0 of `Fire1`–`Fire6`. Only the first keyboard binding of each can be changed. "Down" (S) and the arrow keys are fixed.

1. [`KeyBindingPanel`](../Assets/Scripts/Gui/MainMenu/KeyBindingPanel.cs) in the settings runs interactive rebinding on its own `InputActions`.
2. `Configuration.Create(actions)` reads the override paths that differ from the defaults. `ToJson()` writes them as a small JSON object (only changed keys), or `null` when nothing changed.
3. The panel stores the JSON in `IGameSettings.KeyBindings` and fires `KeyBindingsChangedSignal(json)`.
4. `InputSystemKeyboard` reads the JSON at creation and on the signal: `Configuration.FromJson(json).Apply(actions)` calls `ApplyBindingOverride` for each stored path.

`MouseEnabledSignal(bool)` reports the "use mouse" setting to `InputSystemMouse`. Both signals are bound in `GameInstaller` and `TestSceneInstaller`.

### Regenerating the input code

Edit `Assets/InputActions.inputactions` in the Input Actions editor. Unity regenerates `InputActions.cs` (the asset has code generation on, with namespace `Services.Input`). If you rename the composite parts or the fire actions, update `Configuration`, which finds bindings by name.

## Timer

[`Timer`](../Assets/Modules/GameServices/Scripts/Legacy/Timer.cs) measures intervals with `DateTime.Now`. While the static `Timer.Paused` is set, it restarts the interval. The application services update `Timer.Paused`, but no code creates a `Timer`. The class is dead.
